- **现象**：原始 `source=pymupdf4llm && formulas=0` 的旧状态目标共 40 篇，其中 34 篇仍在当前 `paper_list.csv`。对子任务样本 `2601.03519 / Zhang2026VisionLanguageAction` 运行 marker 重转，单篇 300 秒超时，成功 0 篇；同一样本用临时 `PROJECT_ROOT` 重跑 `fetch.sh`，arXiv e-print 是 PDF document，返回 `source-pdf-only`；缓存模型后用加速参数重跑 marker，97.5 秒后报 `RuntimeError: Invalid buffer size: 16329976999.71 GiB`，未生成 MD。
- **原因**：会话中只验证到 `marker_single` 对该 PDF 在 300 秒内无法完成，且缓存后会在当前本机 torch/surya 配置下崩溃；该样本也无 LaTeX source 可走 pandoc。尚未证明所有 PDF 都不可转，但用 marker 在主会话批量重转不具备可操作性。
- **解决**：已停止批量 marker 重试，保留 pymupdf4llm 兜底结果；最终不声称公式修复达标。
- **预防**：后续若继续修公式，应改成离线批处理/远端长任务，并预先定义单篇 timeout、日志、成功率和替代转换器，不在主 session 中直接跑几十篇 marker。
