## 昨日 50q run 没有硬日志耗时
- **现象**：`2_experiment/runs/20260625_t14_9method_50q_remote_20260625_142901.log` 只保存最终 JSON，没有 start/end/duration；`run_config.json` 的 `created_at_utc` 是产物创建时间，不是运行开始时间。
- **原因**：昨天启动远端评测的 wrapper 没有显式写 timing 文件，日志也没有保留命令启动时间。
- **解决**：只能根据 log 文件名 `142901` 和远端产物 mtime `2026-06-25 14:52:53 -0400` 推断耗时约 23 分 52 秒；该数字必须标注为“文件名+产物时间推断”，不能当硬日志引用。
- **预防**：后续正式远端 run 必须写 `run_timing.json`（start/end/elapsed/returncode/command/source_head），并显式传 `--source-head`，避免再次出现 `source_head: unknown` 和耗时不可追溯。

## macOS rsync 参数与中断残留
- **现象**：本机 macOS 自带 rsync 不支持 `--info=stats2`，命令直接失败；改用 `--stats` 后开始同步。用户中断 turn 后，rsync 仍在后台继续跑。
- **原因**：本机 rsync 版本较旧；Codex turn 被中断不等于已启动的子进程自动退出。
- **解决**：改用兼容参数 `--stats`；发现残留进程 `rsync ... gpu3070ti-relay:~/ForestNav/` 后手动 kill。本次正式 11-method 50q run 尚未启动。
- **预防**：长同步/远端 run 被用户打断后，下一步先 `ps` 检查 `rsync`/`ssh`/`tmux`/`python` 残留，再决定继续、等待或终止。

## 远端缺 matplotlib 但不影响评测
- **现象**：`gpu3070ti-relay` 的 ForestNav venv 有 `numpy/scipy/pandas`，但没有 `matplotlib`。
- **原因**：远端评测环境只满足 runner 数据产出，不包含本地图表绘制依赖。
- **解决**：评测在远端跑，图表在本机用同步回来的 CSV/JSON 生成。
- **预防**：不要把远端 matplotlib 缺失误判为主评测 blocker；只有远端直接画图时才需要安装。
