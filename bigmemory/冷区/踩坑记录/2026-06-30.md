## WebFetch 自动压缩：请求"返回原文全文"仍被摘要

- **现象**：WebFetch 拉取 arXiv HTML 时，即便明确要求"返回原文全文不要压缩"，返回的仍是 AI 总结/压缩版本而非原始文本
- **原因**：WebFetch 底层对长文档有自动截断+摘要逻辑，无法通过 prompt 完全关闭
- **解决**：分多段拉取（每次指定具体章节标题或段落范围），或用更精确的 prompt 指定"只返回 [Section X] 的原文，不要总结"
- **预防**：长论文翻译时默认分节抓取，不要一次请求全文；翻译完成后对照原文章节结构做完整性校验

## symlink vs copy 混淆：key-papers 目录文件修改不同步

- **现象**：`1_survey/learned-heuristic-key-papers/` 中的 MD 文件修改后，`1_survey/papers/md/` 中对应文件未更新（反之亦然）；Dr Sun 读到的是旧版
- **原因**：key-papers 目录中的 MD 文件是独立拷贝而非符号链接，两处文件互相独立
- **解决**：确定以 `papers/md/` 为单一真源；key-papers 目录后续改为用符号链接 `ln -s ../papers/md/<file>.md`，或完全废弃 key-papers 目录直接在 `papers/md/` 读
- **预防**：创建文件集合目录前先决定"真源在哪"；若需聚合多处文件，优先用符号链接而非拷贝

## AI 翻译论文四类常见质量问题

- **现象**：（1）公式双反斜杠（`\\mathcal{G}` 而非 `\mathcal{G}`）；（2）图片全部堆在文末未随正文插入；（3）大段直接引号堆砌，接近重复粘贴而非翻译；（4）混入 AI 主观评论（"这种方法很有创意"等）
- **原因**：模型在翻译时将 LaTeX 转义字符误处理、图片引用与正文段落脱节、直接复用原文而非转述、没有严格限制输出为翻译文本
- **解决**：翻译 prompt 明确要求"忠实翻译，不添加评论；图片 alt 文字紧跟对应段落；公式保持单反斜杠"；完成后做公式渲染检查（`grep '\\\\' <file>`）
- **预防**：建立翻译 QA checklist：① 公式检查 ② 图片位置检查 ③ 搜索主观评论关键词（"很有""非常""优雅""创意"）④ 对比原文章节数和标题数

## arXiv 图片 URL 格式不统一导致下载失败

- **现象**：用 `https://arxiv.org/html/<id>/x1.png` 格式请求图片，返回的是 HTML 错误页面而非图片文件
- **原因**：不同 arXiv 论文的图片 src 路径格式不统一，无法从论文 ID 直接推断图片 URL；有的用 `figures/fig1.png`，有的用 `x1.png`，有的有子目录
- **解决**：先 WebFetch HTML 页面，提取 `<img src="...">` 中的实际路径，再拼接完整 URL 下载
- **预防**：凡需下载 arXiv 图片，务必先抓 HTML 页面提取 img src，不要猜测 URL 格式
