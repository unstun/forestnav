- **背景**：ForestNav 文献库中存在 PDF-only、公式丢失和转换质量风险，需要确认 MinerU 是否适合批量修复科学论文 Markdown，而不是直接用未校验工具覆盖主库。
- **来源**：
  - https://mineru.net/apiManage/docs
  - https://github.com/opendatalab/MinerU-Ecosystem

- **关键发现**：

  - 官方文档显示账号每天有 1000 页最高优先级解析额度；批量接口支持异步提交和轮询。

- **结论**：MinerU VLM 可以作为 ForestNav 文献库 PDF/公式风险修复的主路径，但必须采用 staged 输出和 quality gate：先写入 `1_survey/papers/api_trials/`，通过公式、图片和文件完整性检查后再替换主库 Markdown 与 `_figs`。

## 08:38 — F-N3P vs vanilla_ha 真实"快/好"权衡（配对实验核验）

- **背景**：需要确认 F-N3P 相对 vanilla_ha 的真实性能权衡，辨别均值/中位问题与尾部问题。
- **来源**：`.pipeline/experiments/20260621_t14_formal_6method_rs_k20_collisionguard_validation_t06`，配对 n=242。
- **关键发现**：
  - 快：中位规划时间 11×（Easy 17× / Extreme 10×），搜索节点均值少 3.8×，成功率 80.7%→97.3%（+16.6pp）。
  - 退化按严重度排序：① direction_switches/倒车：0.10→0.84（+8.4×），Extreme 桶 49% 查询有倒车，p95=6；② 膨胀 P95 25%（越难越糟，Extreme 26.4%）；③ 平均曲率/最小净空反而更好，零碰撞。
  - 根因：KNN 子目标可达性在难图失准 → F1 回退 Extreme 桶触发率 94%（均 20.8 次/query）→ 同时制造倒车+膨胀尾部。
- **结论**：F-N3P 退化是尾部+难图问题，非均值问题；头号问题是倒车（direction_switches）而非膨胀；motivation 须从"均值膨胀"改成"尾部/倒车退化"。

## 08:38 — DQN10 可移植车式基线盘点

- **背景**：为 ForestNav 论文 baseline 选型，盘点 DQN10 项目已有的 Ackermann 车式算法，判断哪些可搬迁。
- **来源**：`/Users/sun/tongbu/study/phdproject/dqn/DQN10`（本地仓库实测）。
- **关键发现**：
  - 主算法 MD-DQN：CNN-DDQN + Dueling + Munchausen + DQfD（专家示范预训练）+ AM（Action Mask），Discrete(35) Ackermann，轴距 0.6m / δmax 27°，与 ForestNav 同车型。
  - 整套可移植车式基线（均 Ackermann）：Improved-HA*（Dang2022）/ LO-HA*（Chen2025）/ Lian2023 EHA*+NLP / Spline-SS-RRT*（Yoon2017）/ iDb-RRT / Adaptive-APF（Kilic2026）/ SLSQP-MPC 跟踪器 / Chaikin 平滑 / Dual-Baseline-Expert。
  - ForestNav `third_party/` 已有未接评测的 LO-Hybrid-A* 与运动学 RRT*。
  - MD-DQN 权重 .gitignore 且在 realmap 分布训练，要作为公平基线需在 forest 分布重训。
  - DQN10 论文 SR 86% 与实测 raw_48.csv（DDQN72%/DQN88%）有最高严重度溯源争议，不可直接引用数字。
  - "MD"命名两 agent 说法不一（Munchausen+Dueling vs MHA+Dueling）；run 名 munch_duel + config `munchausen:true` 支持前者，待最终敲定。
- **结论**：DQN10 提供完整 Ackermann 基线套件，但 MD-DQN 需重训且 SR 数字存争议；有效标准基线 = Hybrid A* + 改进 HA* + 运动学 RRT*；普通 holonomic A*/RRT 只能作非车式下界。

## 08:40 — 🔴 ForestNav md_dqn 假基线确认（从 DQN10 盘点中析出）

- **背景**：DQN10 基线盘点过程中追溯 ForestNav 的 md_dqn 实际加载的模型版本，发现与代码默认值不符
- **来源**：
  - `md_dqn_adapter.py:22`（默认 algo='cnn-dqn'）
  - 远端实验命令（实际用 `--md-dqn-algo mlp-dqn`，命令行覆盖默认值）
  - ckpt 文件名 `2026-05-12..._smoke/mlp-dqn.pt`（烟雾测试产物，realmap 分布）
  - `agents.py:912-983`（load() 按权重内 network 重建，ckpt 决定实际架构）
  - 实验报告 `20260620_t14_candidate_6method_fullscale_md_dqn/analysis.md`
- **关键发现**：
  - 名义上的 md_dqn 应为 CNN-DQN（代码默认），实际跑的是 MLP-DQN——DQN10 最旧最弱变体
  - MLP-DQN 缺少全部 6 项增强（CNN、Double DQN、Dueling、Munchausen、DQfD 专家预训练、Action Mask）
  - 实跑结果：Easy SR=0.00 / Complex SR=0.02 / Extreme SR=0.01，300 个场景中 297 个失败
  - ckpt 是 realmap 烟雾测试产物，不是 forest 分布专训——训练分布与评测分布不匹配
  - 之前所有包含 md_dqn 的实验对比结果中，"优于学习基线"的结论不成立
- **结论**：ForestNav 目前唯一的学习类基线是不工作的假基线。必须在 Contract 中正式处理：要么在 forest 分布上重训完整 MD-DQN 并达到合理 SR，要么将 md_dqn 标注为"failed/不可达"并从基线集中移除
