# Hybrid A* 完全解析

一、它到底解决什么问题
普通 A* 在网格上搜索，节点是格子中心，边是"上下左右斜"。这样的路径有两个致命伤：车开不了（Ackermann 车不能原地转向、不能横移，路径处处是折角）；航向缺失（网格节点没有朝向 θ，无法表达"以什么姿态到达"）。

Hybrid A* 的核心思想一句话：在连续状态空间 (x, y, θ) 里用真实运动学生成边，但借用离散网格做剪枝去重。"Hybrid（混合）"指的就是这一点——节点携带连续精确状态，去重用离散格子。这样每条边都是车真实能走的圆弧，而搜索复杂度仍被网格规模封顶。

整个算法由四根支柱撑起，后面逐一拆解：

1. 运动基元扩展：从当前连续状态用自行车模型积分出若干条圆弧（§四、§五）
2. 双启发式：max(带障碍无运动学, 带运动学无障碍) 两个下界互补（§七）
3. 解析扩展（RS 临门一脚）：周期性尝试用 Reeds-Shepp 曲线直接解析连到终点，成功即终止（§八）——这是模块2要替换的槽位
4. 后处理平滑：共轭梯度优化 + Voronoi 场，把网格味的路径磨成光滑轨迹（§十三）

二、一次 plan() 的完整流程
入口是 `planner.py:358` 的 `plan(start, goal, timeout=5.0, max_nodes=20000)`：

```
起终点碰撞自检 ──失败→ 直接返回 failure_reason
      │
预计算 2D Dijkstra 距离场（holonomic 启发式，按 goal 缓存）
      │
起点入 open ──→ ┌─────────── 主循环 ────────────┐
                │ 1. 弹出 f 最小节点（懒删除跳过陈旧堆条目）  │
                │ 2. 到达终点容差内？→ 回溯路径返回          │
                │ 3. 每隔 interval 次扩展：试 RS 解析扩展    │
                │    成功 → 树路径 + RS 尾巴，立即返回        │
                │ 4. 对 10 个运动基元逐一：                  │
                │    积分圆弧 → 沿弧碰撞检测 → 算 g/h →      │
                │    同格 tie-breaker / closed / open 支配检查 │
                │    → 存活者入 open                        │
                └──── 超时 / 超节点数 / open 空 → 失败 ──────┘
```
失败时返回空路径和明确的 failure_reason（start_in_collision / goal_in_collision / open_set_exhausted / timeout / node_budget_exhausted，`planner.py:502-511`）。

三、状态空间与离散化——"Hybrid" 的本义
节点定义在 `planner.py:17-28`：Node 存的是连续的 `AckermannState(x, y, θ)`，外加 g、h、父指针和产生它的基元。

去重键由 `_discretize` 生成（`planner.py:116-121`）：

* x, y 按 `xy_resolution`（默认 = 地图分辨率）floor 到格子索引
* θ 归一化到 `[0, 2π)` 后均分 `theta_bins = 72` 个桶，即 5° 一桶

关键机制：每个 (gx, gy, θ_bin) 三维格子里只保留一个连续状态代表（open/closed 都是 `dict[cell → Node]`）。同一格子里后来者必须 g 更优才能顶掉前任。这就是复杂度上界 = 格子数 × 基元数的来源，也是理论性质受损的根源（§十二）。

为什么可行：两个落在同一 5°×1格 桶里的状态，从它们出发的可达集几乎重合，保留 g 更小的那个足够好——这是精度换速度的核心赌注。

四、运动学模型：自行车模型 + 精确圆弧积分
`robot.py` 定义了一切运动学：

* 参数（`robot.py:9-16`）：轴距 `wheelbase = 0.6 m`，最小转弯半径 `min_turn_radius = 1.1284 m`。最大前轮转角是导出量：`max_steer = atan(L / R_min) = atan(0.6/1.1284) ≈ 28°`。这保证了 `κ_max = tan(δ_max)/L = 1/R_min` 严格自洽——规划器的曲率上限和 RS 曲线的曲率上限是同一个数，两者才能无缝衔接。
* 积分（`robot.py:29-54`）：恒定转向角下自行车模型的轨迹是精确的圆弧，曲率 `k = tan(δ)/L`。代码直接用解析解：
  * `dθ = ds·k`
  * `x' = x + (sin(θ+dθ) − sin θ)/k`
  * `y' = y − (cos(θ+dθ) − cos θ)/k`
  * 而不是欧拉小步近似——零积分误差，直线情形（|k|<1e-8）退化为平移。这个细节很重要：节点状态经过几百步扩展也不会漂移，RS 尾巴对接时姿态才是准的。
* `sample_constant_steer_motion`（`robot.py:77-113`）把一条弧按 `collision_step` 均匀采样出中间位姿序列，供碰撞检测用。采样步长由 `common.py:28` 给出：物理定长 0.1 m，夹在 [0.05, 0.2] m——刻意与地图分辨率解耦，保证不同分辨率地图下碰撞检测密度一致、结果可比。

五、节点扩展：运动基元
`primitives.py:15-27` 生成 10 个基元 = 5 个转向桶 × {前进, 倒车}：

| 转向角 | −28° | −14° | 0° | +14° | +28° |
| --- | --- | --- | --- | --- | --- |
| 对应转弯半径 | 1.13 m | 2.41 m | ∞ | 2.41 m | 1.13 m |

* 每个基元弧长固定 step = 0.3 m；倒车基元自带 weight = 1.2 的代价系数（"slight reverse penalty" 写在基元里，而非 planner 参数——planner 的 `reverse_penalty` 默认 1.0 是中性的，两处不要混淆）
* 满舵 0.3 m 弧的航向变化 ≈ 15.2°（约 3 个 θ 桶），半舵 ≈ 7.1°
* 一个经典工程矛盾：教科书建议基元弧长略大于格子对角线，保证子节点一定"跳出"父节点格子；这里弧长固定 0.3 m，粗分辨率地图下可能落回同格。这套实现不是靠加长弧，而是靠同格 tie-breaker（§十一）来化解——两种方案等效，后者不牺牲路径分辨率。

六、代价函数 g：给一段弧定价
`_transition_cost`（`planner.py:133-145`），注释标明是 thesis 风格代价模型——转弯/倒车是乘法，换向是加法：

```
cost = |弧长| × primitive.weight          # 基础：走过的米数（倒车基元自带 ×1.2）
     × reverse_penalty   (若倒车)          # 默认 1.0
     × turning_penalty   (若打舵)          # 默认 1.05
     + direction_change_penalty (若换向)   # 默认 +2.0
     + steering_penalty × |δ|             # 默认 0（关闭）
     + steering_change_penalty × |Δδ|     # 默认 0（关闭）
```
设计逻辑：乘法惩罚随路径长度自动缩放（"绕远的弯"比"近处的弯"更贵），加法惩罚是一次性事件计费（换一次向 = 固定 +2.0，等价于多走 2 米，直接压制无谓的前后倒腾）。cusps（换向次数）也会在结果统计里单独上报（`planner.py:592-596`）。

七、双启发式：max 的艺术
`_heuristic`（`planner.py:176-195`）取 `h = max(h_holo, h_RS)`，这是 Dolgov 设计中最精妙的一笔。两个启发式各自"故意忽略问题的一半"：

**`h_holo`：带障碍、无运动学（holonomic-with-obstacles）**
* 在占据栅格上从终点反向跑一次 2D Dijkstra（`holonomic_heuristic.py:8-70`），8-连通，得到每个格子到终点的最短绕障距离场
* 它看得见死胡同和 U 形墙——纯欧氏距离会把搜索灌进死路，`h_holo` 直接给死路标上天价
* 按 goal 缓存（`planner.py:400-409`），同一终点多次规划只算一次
* 细节：`_holonomic_cost_to_go` 做了格心偏移修正 `max(0, d − (offset + goal_offset))`（`planner.py:165-174`），把"查询点不在格心"造成的量化高估扣回去

**`h_RS`：带运动学、无障碍（non-holonomic-without-obstacles）**
* 当前姿态到目标姿态的 Reeds-Shepp 最短长度（忽略一切障碍）
* 它看得见姿态代价——终点就在眼前 2 米但车头反了 180°，欧氏距离说"快到了"，`h_RS` 说"你还得画一个 ≥ 转弯半径尺度的调头曲线"。没有它，搜索会在终点附近反复"擦肩而过"
* 性能门控：只在 `h_holo ≤ 15 m` 时才算 RS（`planner.py:186`），因为远处 `h_holo` 几乎总是更大，算 RS 白费；RS 求解失败时兜底用"直线距离 + R_min·|Δθ|"

为什么取 max：每个启发式都是（近似的）真实代价下界，两个下界取 max 仍是下界，且总取信息量更大的那个——近处 `h_RS` 主导（姿态约束紧），远处、有死路时 `h_holo` 主导（拓扑约束紧）。

诚实的理论脚注：严格说这套 h 不是完全 admissible——8-连通网格距离最坏比连续最短路长约 8%（octile 几何效应），兜底公式"直线+R·Δθ"两项相加也可能高估。但 Hybrid A* 本身就不保证最优（§十二），这里用轻微高估换更强的引导力，是清醒的工程取舍。

八、解析扩展：RS"临门一脚"——模块2的主战场
这是理解我们模块2的关键，值得逐行看。

动机：离散基元扩展要把 `(x, y, θ)` 同时逼进 `(0.1 m, 5°)` 容差极其费劲——最后几米的"精确泊入"可能消耗全程大半的扩展次数。解析扩展的思路：别搜了，直接用 RS 闭式解把当前状态和终点连起来，碰撞检测通过就宣布收工。它一石二鸟：终点姿态精确命中（解析解按构造精确），且大幅提前终止搜索。

触发节奏（`planner.py:197-202` + `454-456`）：每 interval 次扩展试一次，`interval = round(8 × clamp(d/10, 0.2, 1.0))`——离终点 ≥10 m 时每 8 次扩展试一次，≤2 m 时每 2 次试一次。离目标越近试得越勤，因为近处 RS 无碰撞的概率越高。这是对 Dolgov 原文"频率随启发式值下降而升高"的实现。

本实现的升级版：Dang 2022 多曲率扫描（`planner.py:204-245`）。标准 Hybrid A* 只用最小转弯半径打一发 RS；这里按曲率步长 `Δκ = 0.05 rad/m` 扫描 `κ ∈ [1/(2×R_min), 1/R_min]`（约 10 个候选半径 1.13~2.26 m），每个候选：
1. `_try_rs_with_radius`（`planner.py:282-340`）：算该半径下的 RS 路径 → 把每段 L/R/S 翻译回运动基元（该半径对应转向角 `atan(L/r)`）→ 按 0.1 m 步长采样 → 全弧碰撞检测，任何一段碰了整条作废
2. 幸存者用 Dang Eq.3 打分（`planner.py:247-280`）：`G = 0.4·v + 0.6·m`，其中 v = 1/路径平均障碍间隙（碰撞风险，EDT 均值），m = 路径长 + Σ|转向角| + 换向次数（运动代价）
3. 取 G 最小者，拼到树路径后面立即返回

直觉：更平缓的曲率（大半径）路径更舒展但更容易蹭障碍，更紧的曲率灵活但绕；多曲率扫描给了 RS 一点"避障的自由度"。代码注释里有两处诚实的 NOTE：v 项用 EDT 近似了原文的 Voronoi 边距离（丢失通道中心线信息，窄通道区分度可能不足）；m 三分量量纲不齐（米/弧度/次数），权重取 1 硬加。

模块2的靶心就在这：RS 是"无障碍最优"曲线，森林这种高密度障碍下它反复被碰撞检测枪毙，白白烧掉大量检测；且它只有 L/R/S 三种字母。我们的 PPO 转向策略做闭环 rollout（每步看局部占据 patch，输出连续曲率），生成的是天生绕障的连接曲线，末端 1-2 m 再切回 RS 精确对接——替换的正是 `_try_analytic_expansion` 这个函数的职责，触发节奏、碰撞把关、立即返回的语义全部保留。

九、Reeds-Shepp 曲线本体
`reeds_shepp.py` 是教科书式实现。RS 理论（Reeds & Shepp 1990）证明：曲率有界、可倒车的车，两姿态间最短路径必属于有限个"字词"家族，每段只有三种字母——L（左满舵圆弧）、R（右满舵圆弧）、S（直线），段可正可负（负 = 倒车）。

实现结构：
* 归一化（`reeds_shepp.py:259-270`）：把目标变换到"起点在原点、朝向 0、转弯半径 = 1"的规范坐标系，解完再把段长乘回 R。所以 12 个族函数只需处理规范情形
* 12 个基础族（`reeds_shepp.py:229-242`）：LSL、LSR、LRL（3 个变体）、LRLR（2 个变体）、LRS_L、LRS_R、LS_R_L、LSL_R、LRS_LR——覆盖 CSC / CCC / CCCC / CCSC / CCSCC 各形态，每个用平面三角几何闭式求解段长
* 4 重对称变换（`reeds_shepp.py:275-326`）：每族再做 timeflip（时间反演 = 全段取负，倒着走）、reflect（镜像 = L↔R 互换）、两者叠加，12 × 4 = 48 条候选，取总长最小者
* 输出 `ReedsSheppPath(segment_types, segment_lengths, total_length)`，带符号段长，负值即倒车段——planner 拿到后逐段翻译回 (转向角, 方向, 弧长) 基元

一个易错细节：`_mod2pi` 特意保留 +π 不映成 −π（`reeds_shepp.py:20-32`），因为族可行性判断依赖角度区间的开闭端。

十、碰撞检测：三种检测器
`geometry.py` 提供了一个小型碰撞检测体系，理解它对模块2尤其重要（RL 环境与规划器必须用同一套碰撞语义）：

1. **`GridFootprintChecker`（矩形足迹，默认）**（`geometry.py:262-416`）
   * 预计算：对 72 个航向桶，各算一次"旋转后的车身矩形覆盖哪些格子偏移"（`geometry.py:215-259`，判据是格心落在旋转矩形内 + 可选 padding）。运行时一次位姿检测 = 偏移数组平移 + `occ[cy, cx].any()`，纯 numpy 向量化
   * 位姿级缓存：`(gx, gy, θ_bin) → bool`，20 万条封顶（同一格同一朝向反复查询是常态，命中率很高）
   * 出界即碰撞（`geometry.py:325`）：未知区域按障碍处理，保守
   * 近似性：格心判据是分辨率级近似（薄角擦碰可能漏检），padding 是补偿手段
2. **`TwoCircleFootprint`（双圆保守覆盖）**（`geometry.py:66-177`）：车身矩形用前后两个圆盖住（`from_box` 自动算圆心距和半径，保证圆并集 ⊇ 矩形），检测退化为两次"圆 vs 格子方块"的精确相交测试（`geometry.py:335-366`）。保守（假阳性）但绝不漏检，且支持 `center_shift`（位姿参考点在后轴而非几何中心的情形）。
3. **`EDTCollisionChecker`**（`geometry.py:419-518`）：预计算欧氏距离变换场，双圆足迹检测退化为两次双线性插值查表：`dist(圆心) ≤ r + √2/2·cell` 即碰撞。注释明确写着"identical to the DRL environment's collision detection in UGVBicycleEnv"——这是规划器与 RL 环境共享碰撞语义的桥，模块2的 PPO rollout 在规划器内做碰撞检测时用它，训练和推理看到的世界才一致。它还把地图边界距离并进了距离场（`geometry.py:449-458`），出界天然被判碰。

路径级检测：所有弧都被采样成 0.1 m 间隔的位姿串逐个检查（`collides_path`）。0.3 m 的基元弧约查 4 个位姿。

十一、Open/Closed 列表的工程细节
主循环（`planner.py:414-500`）有三个容易被教科书忽略、但实现必须处理的机关：

1. **懒删除堆**。`heapq` 不支持 `decrease-key`，所以 open 是 `dict[cell → Node]` + 堆里存 `(priority, 插入序号, cell)`。弹出时若 dict 里已没有该 cell、或 dict 中节点的 priority 与堆条目对不上（说明该 cell 后来被更优节点顶替过），直接跳过（`planner.py:427-434`）。插入序号做平局稳定排序。
2. **同格 tie-breaker**（thesis Algorithm 6）。子节点落回父节点同一格时（0.3 m 弧没跳出格子），正常逻辑会当场判死——父格刚进 closed，g 又不可能更小。特殊放行规则（`planner.py:486-488`）：只要子节点的 f 不比父节点的 f 差超过 `ε = 1e-3`，就允许它顶替父格继续活。效果：允许"格内爬行"逼近目标姿态，而 ε 上限阻止在格内无休止打转。这是粗网格 + 短弧组合能工作的关键补丁。
3. **双重支配剪枝**。跨格子的正常情形：目标格在 closed 里且旧 g 不比新 g 差 → 剪；在 open 里且旧 g 不比新 g 差 → 剪（`planner.py:490-496`）。注意支配只比 g 不比 f——同格子里 h 相近，比 g 即可。

优先级用 `f = g + heuristic_weight × h`（默认权重 1.0；调大即 weighted A*，更贪但更快）。

十二、终止条件与理论性质——必须心里有数的三件事
到达判定：位置误差 ≤ 0.1 m 且航向误差 ≤ 5°（`planner.py:123-128`）。三条终止路线：正常弹出即达标、解析扩展直连、资源耗尽失败。

* **Hybrid A* 不完备**。每格只留一个代表状态：如果通往解的唯一路线需要"本格里另一个姿态"，而那个姿态因为 g 略差被顶掉了，解就永远丢了。基元集有限（10 个）也会漏掉需要中间转向角的解。分辨率越粗、θ 桶越少，丢解风险越大。
* **Hybrid A* 不最优**。三个来源叠加：格内代表剪枝（同上）、启发式轻微不可采纳（§七脚注）、解析扩展先到先得——第一次无碰撞 RS 直连立即返回，即使多搜一会儿能找到更短的组合（Dang 多曲率扫描只在"本轮候选内"选优，不改变这个性质）。

所以对它的正确期望是：分辨率意义下的高质量可行路径，快，但别拿"最优"做论文 claim。Dolgov 原文同样只声称接近最优 + 靠后处理提质。这也是我们实验评价指标要用路径长度/换向数/间隙等相对比较而非"最优率"的原因。

十三、后处理：Dolgov §3 平滑管线
搜索输出的路径是 0.3 m 折线拼弧，网格味重。`smoother.py` 按 Dolgov 2010 §3 实现三步：

1. **共轭梯度平滑**（`smoother.py:203-361`）。把路径顶点坐标当优化变量，目标函数四项加权（对应论文公式 (1)）：
   * 平滑项：权重 0.4，相邻位移向量二阶差分平方，拉直折角，恒在
   * 障碍项：权重 0.2，`(d_obs − d_max)²`，把点推离障碍，`d_obs < 2 m` 时生效
   * 曲率项：权重 0.4，离散曲率 `κ_i = Δφ/Δx`
   * Voronoi 项：权重 0.1，沿 Voronoi 势下降方向推，`d_obs < 2 m` 时生效
   * 优化器是 Polak-Ribière 非线性 CG，带一整套数值保险：梯度 NaN 清洗、模长裁剪（单步 ≤ 半格）、固定小步长（0.05×分辨率）、β 裁剪到 [0,2]。障碍/曲率/Voronoi 梯度全用中心差分数值算——比解析梯度慢但稳。
2. **碰撞锚固**（`smoother.py:157-182`，论文 §3.2）：CG 可能把点平滑进障碍。每轮优化后重查碰撞，碰了的点锚回原始 A* 位置并冻结，再优化，至多 10 轮——原始路径本身无碰撞是这个策略的正确性来源。起终点恒锚定。
3. **非参数插值**（`smoother.py:368-393`，论文 §3.4）：均匀超采样到 ~5-10 cm 点距。代码注释坦承一处与论文的偏离：原文在密集点上做第二轮 CG 精细化，实测容易发散，故只在粗点上做 CG、密集化只做线性插值。

Voronoi 场是这里的点睛之笔（`smoother.py:32-81` 实现 Dolgov Eq.6；`voronoi_field.py` 另有 Dang Eq.2 版本，结构同源）：三因子乘积 `(α/(α+d_o)) · (d_v/(d_o+d_v)) · ((d_o−d_o_max)²/d_o_max²)`。与朴素 EDT 排斥场的本质区别：通道中心线（GVD 边，`d_v=0`）上势严格为 0——窄通道里 EDT 场两侧挤压会把代价顶得处处很高、甚至逼得平滑器放弃窄道，Voronoi 场则永远给中心线留一条零势谷底，窄通道可通行性不受宽度惩罚。GVD 在栅格上用 `skimage.medial_axis` 近似（保留到背景距离、不剪分支，注释里解释了为何不用 skeletonize）。

两处代码级 caveat：一是平滑器只在 (x,y) 上优化、航向靠前向差分重估（`smoother.py:450-457`），换向点（cusp）未做分段/特殊锚固处理，含倒车路径过平滑器会把 cusp 磨掉、方向信息丢失——用于倒车场景前需验证；二是曲率项权重下曲率约束是软约束，平滑输出不保证严格 `κ ≤ 1/R_min`。

十五、回到模块2：这套代码里哪些动、哪些不动
对照设计文档的漏斗架构，在这份实现的坐标系里说：

* **动**：`_try_analytic_expansion` 的内部——Dang 多曲率 RS 扫描换成 PPO 转向策略闭环 rollout（每步观测自车系局部占据 patch + 目标相对位姿 → 连续曲率 → propagate 积分一步）；rollout 到达"RS 可对接状态"后，末端 1-2 m 仍走 `_try_rs_with_radius` 的老路精确贴合
* **不动**：触发节奏（`_analytic_interval`）、碰撞把关（rollout 每步过 `EDTCollisionChecker`，与训练环境同源）、成功即返回的语义、双启发式、基元扩展兜底（rollout 失败 → 退回正常扩展，完备性策略不变）、代价模型、平滑器

理解这套代码后，gate#1（成本账 microbenchmark）的问题也就具体了：多曲率 RS 扫描每轮 ~10 次全弧碰撞检测的开销 vs PPO 一次 rollout 的网络推理开销，在森林地图的典型失败率下谁划算——这正是 Contract 前可以先做的事。
