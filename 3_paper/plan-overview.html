总览：一句话说清楚在做什么

问题：阿克曼小车在密集森林占据栅格图上做全局路径规划，原版 Hybrid A* 因搜索空间爆炸经常超时。

方法：学一个"下一步该去哪"的预测器（KNN 查表），把一个长距离难题拆成多段短距离易题，每段用 Hybrid A* 连接。预测失败就回退到原版。

核心继承：从 N3P（泊车场景，预测 1 个位姿）扩展到森林（多个位姿形成序列）。

方法核心：六个关键设计决策

已定 6/6

以下决策 2026-06-12 由 Dr Sun 拍板，记录在设计稿 v1.1 §2。如需修改须说明原因。

#决策点选定放弃方案备注
D1序列机制逐步预测（每步预测一个子目标）缝枚举 A+C 混合N3P 忠实路线
D2输入表示41 维手工特征 + KNN(k=1)深度特征 / 图像输入KNN 为主，MLP 进消融
D3实验范围程序化森林训练 + 未见图 + 真实地图泛化只做程序化森林查重报告要求泛化测试
D4标签规则解析扩展成功点（贪心 RS 可达分段）瓶颈位姿规则瓶颈规则进消融对照
D5旧 DQN 去向降为 RL 基线继续开发对应 N3P 打 HOPE 的角色
D6Learned heuristic 基线降为 optional作为正式基线文献支点核验失败（Takahashi）
离线阶段做什么
  1. 用 maps/forest.py 程序化生成大量森林地图（多密度、多种子）
  2. 用原版 Hybrid A*+RS 全程求解每张图上的多个查询，保留成功路径
  3. 对每条成功路径跑算法 1（贪心 RS 可达分段），切出子目标真值序列
  4. 在每个子目标处提取 41 维特征，与对应的相对位姿 Δ 配对
  5. 建 KNN 样本库（约 12 万条，~20 MB）
在线阶段做什么
  1. 从起点出发，检查 RS 能否无碰撞直达终点
  2. 不能 → 提取 41 维特征 → KNN 查库 → 预测下一个子目标位姿
  3. 校验预测位姿是否 RS 无碰撞可达，不行就试第 2~5 近邻（F1 回退）
  4. 段内 Hybrid A* 连接当前位姿到子目标（解析扩展优先）
  5. 移动到子目标，重复步骤 1~4
  6. RS 能直达终点时收工；全部失败则 F3 回退到原版 Hybrid A*
KNN vs MLP
KNN(k=1) — 主模型MLP — 消融对照
本质查表：找特征最像的历史记录，返回它的位姿拟合函数：神经网络计算出一个位姿
输出一定是训练集中真实走过的位姿可能输出从未出现过的位姿
多模态无问题——只返回一个最近邻有问题——两个可行方向的平均值可能撞障碍
训练零训练，直接存库需梯度下降训练
角色主模型，论文主结果消融实验，证明 KNN 优于 MLP

基线矩阵：5 条基线 + 公平性条款

基线一句话说明证明什么实现状态
原版 HA*+RS 不做任何分解，直接全程搜索 主对照——我们的方法比不分解快多少 已有
N3P 式 K=1 只预测 1 个子目标就交给 HA* "序列"必要性——1 个够不够？（预期：密林不够） 退化版
Voronoi waypoint HA* 用 Voronoi 图/骨架提取 waypoint，HA* 段内连接 "学习"vs"规则"——KNN 学出来的分解点比规则的好吗？ 需实现
瓶颈规则 waypoint 用中轴变换找窄道，在窄道中心放 waypoint "学习"必要性——如果规则就够了，学习模块就没用 需实现
MD-DQN rollout 用旧项目的 DQN 策略逐步出动作 RL 基线——对应 N3P 打 HOPE 的角色 需复评
公平性条款
  • 全部基线共用同一份 pathplan 实现（同一版 Hybrid A*、同一碰撞检测）
  • 全部基线共用同一双圆近似车体模型
  • 全部基线共用同一计时协议（含所有前置计算）
  • 规则 waypoint 基线的 waypoint 间连接也用段内 HA*——唯一变量是"分解点来自哪里"
  • RL 基线计时口径单独定义（逐步出动作直到可接 RS）
Voronoi waypoint 基线的实现方案需要确认
Voronoi 图/骨架提取有多种实现（scipy.spatial.Voronoi、skimage.morphology.medial_axis 等）。用哪种？还是两种都试？是否需要对 Voronoi waypoint 做后处理（比如剪枝太近的 waypoint）？

指标体系：9 个指标 + 计时协议

指标一句话解释怎么比
规划时间 T从收到查询到输出路径的总耗时，包含所有前置计算和回退越小越好，主表报 median 和 P95
节点扩展数 E所有 HA* 搜索的总扩展节点数（含回退里的）越少越好，反映搜索量的减少
成功率 SR在预算内找到可行路径的查询比例不能比原版低太多（≥-2 pp）
路径长度膨胀率我方路径比原版长多少（百分比）只在双方都成功的查询上比，≤5%
方向切换次数路径中前进/倒车切换几次N3P 口径，越少越好
最小安全裕量路径上车体到最近障碍物的最小距离越大越安全，不应比原版差太多
碰撞违例返回路径上是否有碰撞（应该永远是 0）完整性校验，不是比较指标
回退触发率F1/F2/F3 各触发了多少查询（分级报告）F3 >30% = 方法不 work
子目标可达率预测的子目标首次 RS 检测就无碰撞通过的比例越高说明 KNN 预测越准
计时协议
  • 单线程、同一台机器、负载隔离
  • 方法侧全部开销计入 T（特征提取、KNN 查询、RS 校验、段内搜索）
  • 原版 HA* 的 2D 启发式 DP 预计算也计入 T（N3P 公平口径）
  • 统计：≥5 种子 × 每桶 ≥100 查询
  • 主表报 median 与 P95，补充报 min/mean

实验预注册草案：研究假设 + 判定标准

3 项待锁定

实验预注册（pre-registration）= 实验前锁定"什么算成功、什么算失败"，防止实验后编故事。一旦批准不可修改——需改则产出 v2 并写明原因。

待锁定 ①：研究假设的数字——"我们赌方法能达到什么效果"
草案：在困难场景（Complex/Extreme 难度桶），F-N3P 相对原版 Hybrid A*：
• 规划时间中位数缩减 ≥50%（原版用 2 秒，我们应该 ≤1 秒）
• 成功率最多低 2 百分点（原版 95% 则我们至少 93%）
• 路径最多长 5%（原版 20 m 则我们最多 21 m）
以上在未见程序化图 + 真实地图上同时成立，≥5 个随机种子的中位数达标。

需要您判断：50% 提速目标合适吗？N3P 在泊车场景报告超过 80% 提速，但森林更难，所以降到 50%。太高？太低？成功率容忍 2 百分点够不够？路径变长 5% 会不会太严？
待锁定 ②：失败判据——"什么情况说明方法不行"
草案（四条独立，任何一条命中即判方法失败）：
• ① 超过 30% 的查询需要回退到原版 Hybrid A*，且提速消失——说明预测器不靠谱
• ② 在训练时没见过的森林密度（分布外 OOD）上，成功率比原版低超过 5 百分点——说明不能泛化
• ③ 跟手工规则放置子目标的方法没有显著差异——说明"学习"这步没必要
• ④ 在真实 SLAM 地图上提速不到 20%——说明只在"假森林"上有效

需要您判断：30% 回退率红线合理吗？分布外 5 百分点跌幅是不是太严？"没有显著差异"用什么统计方法判定？
待锁定 ③：怎么确认结果不是碰巧——统计检验
问题：跑 100 个查询我们快了 50%，怎么排除"恰好这批查询对我们有利"？

草案（建议纳入预注册）：
• Wilcoxon 符号秩检验：同一个查询，原版用了多久、我们用了多久，逐个配对比较，统计判断"我们确实更快"不是巧合
• 自举置信区间（Bootstrap CI）：反复从结果中随机抽样，看成功率差异的范围是否稳定
• p 值门槛：p < 0.05 = "纯靠运气出现的概率不到 5%"，学术界通用标准

需要您判断：要不要把统计检验纳入预注册？纳入的话用 p < 0.05（通用标准）还是 p < 0.01（更严格）？
