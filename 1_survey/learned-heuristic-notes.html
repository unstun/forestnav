LoHA*: Learning Local Heuristics for Search-Based Navigation Planning
Veerapaneni, Saleem, Likhachev CMU ICAPS 2023 arXiv: 2303.09477
局部启发函数 focal search 有界次优性 Ackermann 4D state-lattice
不学全局 cost-to-go，只学"逃离局部区域的额外代价"——问题规模缩小几个数量级，泛化能力大幅提升，节点展开减少 2-20x，且保留有界次优性保证。
要解决什么问题

以往方法（DeepCubeA、Kim & An 2020 等）学的是全局 cost-to-go h(s)≈h*(s)。三个核心问题：

  • 全局 h 需要对整张地图推理，学习难度随地图变大急剧增长
  • 泛化差——小地图训练的 h 到大地图不 work
  • 训练数据贵——每个样本要求解一个完整规划问题
核心方法

学什么：局部启发函数 hk(s) —— 从状态 s 逃出以其为中心的 K×K 区域需要的额外代价（相对于全局启发函数 hg 的残差）。

hk(s) = hgk(s) - hg(s)

hgk(s) = mins' {
  c(s,s') + hg(s')   if s' ∈ LRB(s)  // 到达边界
  c(s,s') + 0          if s' = goal ∈ LR(s) // 区域内到达目标
  ∞                   otherwise   // 死胡同
}

怎么用：搜索时用 hg(s) + hk(s) 作为启发函数。hg 提供全局方向，hk 修正局部障碍物导致的低估。

怎么保证：用 focal search（Pearl & Kim 1982）—— OPEN 用可采纳的 hg 排序，FOCAL 用 hg + hk 排序，保证有界次优性。

加速倍数 = 基线 weighted A* 的节点展开数 / LoHA* 的节点展开数。w 越大，越依赖启发函数质量，LoHA* 优势越明显。

局限性
  • 墙钟时间没减：NN 推理 ~4,500 节点/秒 vs 普通 A* ~140,000 节点/秒。节点减 10x 但推理慢 30x → 墙钟反而更慢
  • 数据收集贵：每个样本需要在局部区域跑一次 A*（续作 DE-LoHA* 解决）
  • 局部区域必须可定义：依赖物理空间 (x,y) 窗口，不适用于机械臂等场景
与 ForestNav 的关联
直接相关：
  • 同样是阿克曼运动学 + state-lattice 搜索
  • 障碍物密度 20-30% 与森林可比
  • 局部 hk 天然适合识别森林中的"死胡同"——树木间的狭窄通道走不通时 hk 给高惩罚
需要解决的差距：
  • 论文用 2D 栅格，森林是圆形障碍物 → NN 输入表示需适配
  • 墙钟没加速 → 需要 batch inference 或更轻量网络
  • K=4 (9×9) 在森林中是否够覆盖瓶颈区域？
  • 随机障碍 vs 森林结构性障碍（树间距、通道宽度）
2
DE-LoHA*: A Data Efficient Framework for Learning Local Heuristics
Veerapaneni*, Park*, Saleem, Likhachev CMU SoCS 2024 arXiv: 2404.06728
LoHA* 续作 回溯数据收集 在线学习 Ackermann 4D state-lattice
LoHA* 的同组直接续作——利用全局 A* 搜索中的回溯信息"免费"收集局部启发函数训练数据，数据效率提升 10 倍，支持边规划边学习的在线模式。
要解决什么问题

LoHA* 的数据收集瓶颈：每个训练样本需要在局部区域独立运行一次 A* 搜索。当 K 增大时，代价急剧增长（K=16 时需 616 次展开/样本）。

核心洞察
当全局 A* 求解一个 start→goal 问题时，搜索过程中展开的节点已经天然包含了大量局部子问题的解——只需要"回头看"就能提取。

定理 1（全局-局部排序一致性）：全局 A* 中从 s 出发在 LR(s) 内展开状态的顺序，与从 s 出发的局部 A* 的顺序完全一致。

b(s_start, s') = c(s_start, s) + c(s, s') + h_g(s')
             = c(s_start, s) + b(s, s')

c(s_start, s) 是常数 → 排序与局部 A* 一致   QED
方法：回溯数据收集

完整数据：展开 s' 时，沿父指针回溯每个祖先 s。若 dist(s, s') > K（s' 已逃出 s 的局部区域），则 s' 就是 s 的最佳边界状态 → 直接算 hk(s)。

不完整数据：若 s' 仍在 LR(s) 内，记录下界 hgk(s) ≤ c(s,s') + hg(s')。训练时按进度降权：

α(s, s') = d(s, s') / K < 1
训练损失 × α   (离边界越远，权重越低)

零额外计算：不需要碰撞检测、不需要优先队列操作，仅沿父指针链回溯 + 距离检查。

在线学习

从 5 个规划问题的初始数据集开始 → 训练 → 用模型求解新问题同时收集数据 → 每 5 个问题重新训练。

20 个问题后就出现显著性能提升，无需独立数据收集阶段。

局限性
  • 墙钟问题未解决：NN 推理开销仍在（~2.3s/问题 vs 基线 0.1s/问题）
  • 去掉 α 降权后性能从 3.9x 降到 2.4x——不完整数据质量管理很关键
与 ForestNav 的关联
如果走 LoHA* 方向，DE-LoHA* 的回溯数据收集是必用技术—— 森林场景中我们已经在跑大量 Hybrid A* 求解，这些搜索过程中的中间数据可以"免费"用于训练局部启发函数。 在线学习模式意味着不需要预先准备大数据集，可以边跑实验边改进模型。

LHBL: Beyond Single-Step Updates — RL of Heuristics with Limited-Horizon Search
Hadar, Agostinelli, Shperberg Ben-Gurion Univ. / Univ. of South Carolina AAAI 2026 arXiv: 2511.10264
多步贝尔曼标签 凹陷区域修复 DeepCubeA 改进 无运动学约束 离散组合难题
改进 DeepCubeA 的训练方式——用有限视距搜索生成多步训练标签（替代单步贝尔曼更新），解决启发函数的凹陷区域问题。在魔方/拼图上全面优于 DeepCubeA。
要解决什么问题

DeepCubeA 式的单步贝尔曼更新有两个局限：

  • 采样分布不匹配：训练时随机采样状态，但实际搜索时状态分布高度非均匀（偏好低启发值区域）→ 训练和部署的分布不一致
  • 标签信息量不足：每次更新只用到一条边的精确代价，其余全靠不准确的启发值估计 → 容易产生凹陷区域（depression region，启发函数严重低估的区域）
核心方法：LHBL

搜索阶段：从采样状态 s 出发执行 N 步有限视距搜索（A* 或 GBFS），获得搜索图 G。

更新阶段：每个状态的启发值标签不再来自单步贝尔曼，而是来自到搜索前沿最佳后代的完整路径：

单步贝尔曼 (SSBL):
  h(s) = mins'∈succ(s) [c(s,s') + h(s')]   // 1 条精确边 + 1 个估计值

有限视距贝尔曼 (LHB):
  h(s) = minℓ∈leaves [C(s,ℓ) + h(ℓ)]   // k 条精确边 + 1 个估计值

计算方法：在搜索图中添加辅助节点 z，连接所有前沿叶节点（边权 = 叶节点启发值），反转所有边，从 z 跑 Dijkstra → 一次性算出所有节点的 hLHB。

局限性
  • 只在离散组合难题上验证（魔方、拼图、Lights Out）——没有连续状态空间、没有运动学约束
  • 视距 N 过大可能引入近似误差或过拟合
  • 训练代价高（魔方需 10-12 天 / RTX 4090）
与 ForestNav 的关联
LHBL 的思想（多步搜索标签 > 单步贝尔曼标签）是训练方法的改进，与 LoHA* 的"学什么"正交。 理论上可以组合：用 LHBL 的多步标签方式来训练 LoHA* 的局部启发函数。 但 LHBL 本身未在运动学约束场景验证，直接迁移有风险。更适合作为参考思路而非直接采用。
